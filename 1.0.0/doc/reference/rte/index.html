    ECU description (rte.yaml)¶

    Software components, their connections, application tasks and the CAN database of one ECU. The file is named by project.rte in project.yaml, checked against its schema by tools/nxconfig (with file, line and YAML path, before the build) and read by tools/rtegen. What needs the component ARXML, the DBC, the BSW task manifest or the board signals of the project - unknown ports and runnables, the type of a connection, periods and priorities against the BSW tasks, the rules of an E2E profile - is checked by tools/rtegen (--validate, the same messages in neXtBSW Studio).

    Configuration level: Project. File: projects/<project>/rte.yaml. Schema: EcuDescription in tools/nxconfig/model.py.

    39 fields in 8 objects. 0 fields have no description in the schema and 0 numeric fields have no unit; they are marked missing in schema and missing. How to read the tables: reference overview.

    ECU description file projects/<project>/rte.yaml¶

    (top level)¶

    ECU description of a project (projects/<project>/rte.yaml, named by project.rte).

    Software components, the connections of their ports, application tasks and the CAN signals of one ECU; read by tools/rtegen. Values of the ECU state management and XCP are project values (project.yaml) and do not stand here.

    Format 2 (customer-project.md gap N3): components[].path and can.dbc are relative to this file, like project.board is relative to project.yaml. Before that they were relative to the root of the repository, which only exists in the neXtBSW tree itself - a customer workspace has no such root. A file without the key is format 1 and is raised by nxconfig migrate (migrate.STEPS, step rte:2).

    Field Type Unit Required Default Allowed values Description
    schema_version integer yes 2 Version of the file format; currently 2.
    tasks list of object no null at least 1 item Application tasks. Left out: one task with the default name, priority and stack of the BSW task manifest and the period base_period_ms.
    base_period_ms integer ms no null > 0 Only without tasks: period of the one application task. Left out: the greatest common divisor of the runnable periods.
    components list of object yes Software components of the ECU; each name once. []: none yet (empty project, only the BSW runs).
    can object no null CAN signals from a DBC; left out: no CAN signals.
    uds object no null Bus of the application diagnostic stack.
    connections map of string to string or list of string no {} value: at least 1 character; value: at least 1 item; value: item: at least 1 character Port connections, key Component.Port.Element. A required port has exactly one source: a provided port Component.Port.Element, a BSW signal (dio.in.<INPUT>, adc.mv.<CHANNEL>, adc.raw.<CHANNEL>, adc.phys.<CHANNEL>, adc.qlf.<CHANNEL>, a value of a module instance <prefix>.<INSTANCE>.<value> as its module.yaml rte describes it (e.g. capture.<CHANNEL>.<value>, hall.<DEVICE>.<value>, gd.<DEVICE>.<value>), ecu.state, ecu.wakeup[.<source>], a BSW service port bsw.power.<value>, bsw.reset.<value>, bsw.time.<value>), a received CAN signal can.rx.<Message>.<Signal> or qualifier can.qlf.<Message>, a non-volatile block nvm.<Block> (reads the stored value, same type as its writer) or its quality nvm.qlf.<Block>, or rte.init (keeps its init value). A provided port feeds one target or a list: dio.out.<OUTPUT>, pwm.<PAIR>, can.tx.<Message>.<Signal>, ecu.sleep_request, a non-volatile block nvm.<Block> (exactly one writer per block, its init value is the default; definition, place and write policy in project.yaml nvm.blocks), or rte (value stays in the RTE). A mode port (required port with a mode switch interface, key Component.Port.ModeGroup) is connected to the ECU mode manager ecu.mode: its mode declaration group names exactly the ECU states STARTUP, RUN, STANDBY, RUNDOWN, SHUTDOWN and SLEEP, and the component reads the mode with Rte_Mode_<Port>_<ModeGroup>().
    ecu_state any no null Not allowed: the parameters of the ECU state management are project values in project.yaml modules.ecuState.

    tasks[]¶

    One application task of the ECU: FreeRTOS task running the runnables assigned to it.

    The BSW tasks (bsp, can, ...) are not listed here; they come from ecu/asyncCoreConfiguration/tasks.yaml.

    Field Type Unit Required Default Allowed values Description
    tasks[].name string yes pattern ^[a-z][a-z0-9]*$ Task name: lower case letters and digits, starting with a letter (no underscore; idle and timer are reserved). Must not be the name of a BSW task.
    tasks[].period_ms integer ms yes > 0 Cycle of the task, a multiple of the OS tick of the BSW task manifest. Every runnable of the task has a period that is a multiple of it.
    tasks[].priority integer none yes > 0 Ordering key between the BSW tasks of the manifest (e.g. between bsp 20 and can 40); unique over all tasks. The FreeRTOS priority follows from the order.
    tasks[].stack_bytes integer byte yes ≥ 0 Stack of the task; at least min_stack_bytes of the BSW task manifest.
    tasks[].runnables list of object no null Runnables in call order. Left out in every task and only one task: all periodic and mode switch runnables run in it. Otherwise every periodic and every mode switch runnable has to be listed in exactly one task. Mode switch runnables run at the start of a cycle, before the periodic ones: first every on-exit, then every on-transition, then every on-entry runnable, each group in the order of this list.

    tasks[].runnables[]¶

    A runnable assigned to an application task, optionally with a start offset.

    In the list tasks[].runnables an entry may be written as plain text Component.Runnable (offset 0) or as a mapping {runnable: Component.Runnable, offset_ms: 20}. A mode switch runnable is listed the same way and never has an offset.

    Field Type Unit Required Default Allowed values Description
    tasks[].runnables[].runnable string yes at least 1 character Runnable as Component.Runnable (name of the component in components[], runnable of its ARXML): a periodic runnable (TIMING-EVENT) or a mode switch runnable (SWC-MODE-SWITCH-EVENT on entry, exit or transition of an ECU mode; the event is part of the component, the task is chosen here).
    tasks[].runnables[].offset_ms integer ms no 0 ≥ 0 Start offset inside the task: the runnable runs in the task cycles offset_ms, offset_ms + period, ... A multiple of the task period and below the period of the runnable. Not for a mode switch runnable, which runs once at the start of the first task cycle after the mode switch.
    tasks[].runnables[].enabled boolean no true false: the runnable is disabled - it keeps its place in this list but is not called. Required ports of other components that it feeds read a constant value instead: the init value of the provided port, else components[].disabled_values, else the init value of the reading port; a qualifier port reads QLF_NOT_AVAILABLE. Not allowed for a runnable of a safety-relevant component (swc.yaml safety other than qm).

    components[]¶

    A software component of the ECU: its name and the folder with generated/arxml and <Name>_data.m.

    Field Type Unit Required Default Allowed values Description
    components[].name string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ Component name as in its ARXML (Simulink model name, e.g. DemoSwc).
    components[].path string yes at least 1 character Component folder relative to the repository root (tools/rtegen --repo), e.g. swc/DemoSwc. The RTE reads <path>/generated/arxml/*.arxml and the calibration values of <path>/<name>_data.m.
    components[].enabled boolean no true false: the component is disabled - its init and its runnables are not called (it stays compiled; the linker drops the code nobody calls). Required ports of other components it feeds read a constant value instead: the init value of its provided port, else disabled_values, else the init value of the reading port; a qualifier port reads QLF_NOT_AVAILABLE. Not allowed for a safety-relevant component (swc.yaml safety other than qm).
    components[].disabled_values map of string to boolean or integer or number or string or any none no {} Value a provided port (key Port.Element) delivers while the part that writes it is disabled (enabled: false here or at the runnable). Required - and only allowed - for a port without an init value of its own: a C component (swc.yaml has no init values) or an ARXML port without INIT-VALUE (unless every reading port has an init value of its own, or is a qualifier port). A number (physical value of a fixed-point type), true/false, an enumeration literal, or a list for an array or a record. Kept while the part is enabled, so switching it on and off again needs no new entry.

    can¶

    CAN signals of the ECU (section can:): the DBC, the node of this ECU in it and the bus they run on.

    Field Type Unit Required Default Allowed values Description
    can.dbc string yes at least 1 character DBC file relative to the repository root.
    can.node string yes at least 1 character Node of this ECU in the DBC: its messages are sent, the messages it receives are received.
    can.bus string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ CAN bus of the project (board can[].name, used in use.can) the signals run on. Left out: the first CAN bus of the project.
    can.monitor list of string no [] DBC messages whose signals the RTE receives for the console and XCP without a connected port.
    can.task string no null Application task that sends and receives the messages. Left out: the only application task (required with several).
    can.qualifiers map of string to object no {} Supervision per DBC message (key: message name).

    can.qualifiers.<key>¶

    Supervision of one CAN message: timeout, debouncing and error values of the signal qualifier.

    A received message may use every key, a sent message only e2e. A received message without entry keeps the defaults (DBC timeout, no debouncing, values hold).

    Field Type Unit Required Default Allowed values Description
    can.qualifiers.<key>.timeout_ms integer ms no null ≥ 0 Received message: time without a message after which the qualifier reports ERROR_TIMEOUT; 0 switches the supervision off. Left out: GenMsgTimeoutTime of the DBC.
    can.qualifiers.<key>.debounce_ms integer ms no 0 ≥ 0 Received message: an E2E or timeout error must last this long before the qualifier reports it (QLF_DEBOUNCE until then).
    can.qualifiers.<key>.on_error string no "hold" hold, init Received message: signal values while the qualifier reports an error - hold keeps the last valid values, init falls back to GenSigStartValue.
    can.qualifiers.<key>.e2e object no null E2E protection of the message; left out: none.

    can.qualifiers.<key>.e2e¶

    AUTOSAR E2E protection of one CAN message: profile, data id and the DBC signals of CRC and counter.

    Receiving, the RTE checks it and reports errors in the signal qualifier; sending, it writes counter and CRC. Which keys a profile takes is checked by tools/rtegen: P01/P11 data_id (16 bit, NIBBLE: 12 bit) and data_id_mode, P02 data_id_list (16 values of 8 bit).

    Field Type Unit Required Default Allowed values Description
    can.qualifiers.<key>.e2e.profile string yes P01, P02, P11 E2E profile of libs/bsw/e2e.
    can.qualifiers.<key>.e2e.data_id integer none no null ≥ 0 Data id of the message (P01, P11). Left out: 0.
    can.qualifiers.<key>.e2e.data_id_list list of integer none no null item: ≥ 0 P02 only: one 8-bit data id per counter value 0..15 (exactly 16 values).
    can.qualifiers.<key>.e2e.data_id_mode string no null BOTH, ALT, LOW, NIBBLE How the data id enters the CRC (P01: BOTH, ALT, LOW, NIBBLE; P11: BOTH, NIBBLE; not for P02). Case does not matter. Left out: BOTH.
    can.qualifiers.<key>.e2e.data_id_nibble string no null Mode NIBBLE only: DBC signal that carries the high nibble of the data id.
    can.qualifiers.<key>.e2e.crc string yes at least 1 character DBC signal of the CRC.
    can.qualifiers.<key>.e2e.counter string yes at least 1 character DBC signal of the sequence counter.
    can.qualifiers.<key>.e2e.max_delta_counter integer counter steps no 1 > 0 Largest accepted counter jump (MaxDeltaCounter), below the counter range of the profile.

    uds¶

    CAN bus of the application diagnostic stack (ecu/uds). Left out: the bus of the CAN signals.

    Field Type Unit Required Default Allowed values Description
    uds.bus string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ CAN bus of the project (board can[].name, used in use.can) that DoCAN runs on. The diagnostic addresses are project.yaml diagnostics.
