    Console commands¶

    The application has a text console on the UART of the board (how to open it: build and flash, step 8). This page lists every command the neXtBSW application can register, with its syntax, what it does and in which build it exists. It is generated from the sources: the command registration and help texts in the C++ code, the CMake conditions and build options, the module manifests, the projects and the board READMEs. A test fails as soon as page and sources disagree. help on the console shows what the running build really contains.

    How to read this page¶

    • Syntax - <group> <command> [parameters]. Parameters are shown where the help text states them (param: ... or Usage: ...); a command without them may still take parameters - the purpose column then says so in the words of its help text. help <group> prints the commands of one group.
    • Available - the conditions under which the group is built in: the family port it belongs to, the module a project must use, a PLATFORM_SUPPORT_* switch derived from the project and its board (ARCH-58), a CMake build option for test builds. Only in adds conditions of a single command. Always means: in every build of the application.
    • Per-device groups - modules with console: instance in their manifest register one group per board device they serve; its name is the device's console parameter in project.yaml. They are listed as <name>, with the names the projects in this repository use in the project table.
    • Board rule - the command may only be used with a person at the board. The mark comes from the help text, which ends in the marker “(board rule)” (SYS-17; the earlier wordings “only with the user at the board”, “board rules apply” still count, but tools/docgen --gaps reports them), or from the list “Only with a person at the board:” in the README of a board. The marker is what a person at the console sees in help, so every command in a board's list should carry it. Whether a command is dangerous depends on how the board is wired, so the board README is the authority; an unmarked command is not declared safe.
