    Project description¶

    What one ECU software uses of its board: system clock, used buses and channels with bit rates, PWM frequency and dead time, memory partitioning, bootloader and diagnostic addresses, interrupt ranks, loads at ADC channels, safety pins and module parameters. The project is the one input a build starts from.

    Configuration level: Project. File: projects/<project>/project.yaml. Schema: Project in tools/nxconfig/model.py.

    221 fields in 46 objects. 0 fields have no description in the schema and 0 numeric fields have no unit; they are marked missing in schema and missing. How to read the tables: reference overview.

    Project file projects/<project>/project.yaml¶

    (top level)¶

    Project file projects/<project>/project.yaml: what one ECU software uses of its board.

    Field Type Unit Required Default Allowed values Description
    schema_version integer yes 1 Version of the file format; currently 1.
    project object yes Identification of the project; board and ECU description it is built from.
    clock object yes System clock of the project.
    memory object no null Memory partitioning. Left out: no bootloader, no generated memory layout.
    nvm object no null Non-volatile memory: partition of the emulated EEPROM, fixed block places. Left out: chip as it is, blocks in name order.
    security object no null Keys of the hardware security module (flags, name of the MASTER_ECU_KEY in the key store of the workstation). Left out: no keys described.
    bootloader object no null CAN bus and devices of the bootloader.
    diagnostics object no null UDS addresses of bootloader and application; required together with memory.
    xcp object no null XCP on CAN. Left out: no XCP slave in the application.
    use object no {} Board entries the project uses.
    peripheral_clocks map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Functional clock of a peripheral instance; key: instance of the derivative, or a clock gate of clock.pcc. Only needed where the derivative's default is not wanted or where it has none.
    can map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Bit timing per CAN bus; key: board CAN bus, required for every used bus.
    uart map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Baud rate per UART; key: board UART, required for every used UART.
    i2c map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Rate and time limit per I2C bus; key: board I2C bus. A used bus without an entry runs at 100 kHz (standard mode).
    pwm map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ After R1. Frequency and dead time per PWM group; key: board PWM group.
    adc_internal list of object no [] Internal ADC inputs without pin the project reads.
    adc_loads map of string to one of object (kind: ntc_beta) or object (kind: table), selected by kind no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Load connected to a board ADC channel with a sensor circuit, e.g. the NTC of a motor; key: the channel.
    adc_sampling map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Sampling of a used board ADC channel other than one conversion per read, e.g. averaged over one PWM period; key: the channel. Left out: one conversion per read.
    interrupts object no {} Interrupt priorities as ranks.
    pin_events map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Events on digital inputs (pin interrupt on an edge); key: a used board input (dio.inputs[].name). Each one needs a rank (interrupts.ranks, source dio). Left out: inputs are only read as levels (dio.in.<NAME>).
    safety object no null Pins of the OpenBSW safety demo. Left out: none.
    modules map of string to map of string to integer or boolean or string or object unit of the module parameter no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$; value: key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Parameters of the modules; key: board device, or a module with project parameters (project_parameters in its module.yaml) that has no board device. Values are checked against the parameters of that module; verify: true marks the values of an entry as not confirmed. A system basis chip with partial networking (module sbcUja113x) takes can_wakeup_frame in addition.
    hw_thresholds map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ After R1. Hardware thresholds: a board signal at a comparator input that forces a PWM group to its inactive level without software (latched until reset); key: name of the threshold. Left out: none.
    sample_groups map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Sample groups: board ADC channels converted after every hardware trigger of a PWM group, with one interrupt at the end of the group; key: name of the group. Each group needs an interrupt rank (interrupts.ranks, source sample_group). Left out: none.
    bsw_tasks map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Stacks of the BSW tasks (ecu/asyncCoreConfiguration/tasks.yaml: background, bsp, can, sysadmin, safety) and of the OpenBSW tasks idle and timer, or the task a BSW task runs in instead of its own; key: task name. The application tasks take their stack from the ECU description (rte.yaml tasks[].stack_bytes). Left out: the defaults of ecu/configuration/taskStacks.yaml, every BSW task on its own.
    console object no null Console and logger of the application: selectable, size of the logger ring buffer. Left out: console and logger on, ring buffer 8192 bytes.

    project¶

    Identification of the project and the files it is built from.

    Field Type Unit Required Default Allowed values Description
    project.name string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ Project name; by convention the same as the folder projects/<project>.
    project.board string yes Board folder or its board.yaml, relative to project.yaml.
    project.rte string no null ECU description (rte.yaml) for tools/rtegen, relative to project.yaml. Required: the build runs rtegen at every configure, and nxconfig refuses a project that is built without it (TOOL-114). An ECU without software components still has one: one task, components: [].
    project.diag string no null Diagnostic description (diag.yaml): data identifiers, routines, sessions, security levels and DTCs of this ECU software, relative to project.yaml. Left out: the project describes no diagnostic jobs and no fault memory.
    project.description string no null Short description of the project for the reader.
    project.integrity string no null qm, asil_a, asil_b, asil_c, asil_d Highest safety integrity the ECU software of this project carries (ASIL of its safety requirements). qm: no safety requirement; the checks that are stricter for ASIL projects then only warn (e.g. a BSW task stack below its default without a proof note, bsw_tasks.<task>.evidence). Not qm while an NvM block has an ASIL integrity. Left out: treated as an ASIL project - the safety part of neXtBSW (safety task, safe supervisor) is in every image.

    clock¶

    Clock the project runs at; sources, dividers and PLL settings are derived by the family clock model.

    Field Type Unit Required Default Allowed values Description
    clock.system_hz integer Hz yes > 0 Core clock. Sources, dividers and PLL settings follow from it and from the board crystal.

    memory¶

    Memory partitioning (doc/architecture/README.md, section 7). The validity record takes the last sector of flash, the application the sectors between bootloader and record. Addresses follow from the derivative.

    Field Type Unit Required Default Allowed values Description
    memory.flash string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ Code flash region of the derivative (memory[].name, kind code_flash).
    memory.bootloader object yes Flash and RAM of the bootloader.
    memory.application object yes RAM of the application.
    memory.calibration object no null Calibration segment (SYS-89). Left out: the parameter values stay in the initialised data of the application (RTE-03).

    memory.bootloader¶

    Bootloader area at the start of the code flash and the RAM the bootloader (and its updater) runs in.

    Field Type Unit Required Default Allowed values Description
    memory.bootloader.size integer byte yes > 0 Flash of the bootloader from the start of memory.flash; whole sectors.
    memory.bootloader.ram string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ RAM region of the derivative the bootloader runs in.
    memory.bootloader.ram_size integer byte no null > 0 RAM of the bootloader from the start of ram. Left out: the whole region.
    memory.bootloader.stack_size integer byte no 4096 > 0 Stack of the bootloader.

    memory.application¶

    RAM of the application. The no-init area (hard fault dump, boot request) ends at the end of the last region.

    Field Type Unit Required Default Allowed values Description
    memory.application.ram list of string yes at least 1 item; item: at least 1 character, pattern ^[A-Za-z0-9_]+$ RAM regions of the derivative the application uses, in address order and contiguous.
    memory.application.noinit_size integer byte yes > 0 Size of the no-init area at the end of the last RAM region: it survives a reset and holds the hard fault dump and the boot request.
    memory.application.ramfunctions_size integer byte no null > 0 RAM for flash routines that run from RAM (.launchFromRAM), at the start of the RAM. Small derivatives (e.g. 14 KB SRAM) need less than the template default. Left out: the default of the linker template (0x1000).
    memory.application.hot_ram_size integer byte no null > 0 Hot part at the start of the RAM: RAM functions plus hot data and bss. Left out: the default of the linker template (0x2000 with a single RAM region, otherwise the whole first region).
    memory.application.isr_stack_size integer byte no null > 0 Interrupt stack (main stack: start-up up to the scheduler plus every interrupt level nested). Multiple of 8. Size it with the worst case of tools/stackuse for the image plus a reserve. Left out: the default of the linker template (0x1000).
    memory.application.isr_stack_guard_size integer byte no null > 0 Guard directly below the interrupt stack that the core may read but not write (MPU): an overflow ends in the hard fault reaction instead of overwriting data. Multiple of 32 (MPU granularity); it must hold the largest frame on the interrupt stack plus the larger of that frame and an exception frame (tools/stackuse checks it). Left out: the default of the linker template (0x400).
    memory.application.isr_stack_evidence object no null Proof note of the interrupt stack: used_bytes is the worst case on the main stack (start-up plus every interrupt level nested, tools/stackuse --strict for this image) or the high-water mark at the board (inject mspuse). Required for isr_stack_size below the default of the linker template in an ASIL project (project.integrity not qm), otherwise a warning. The interrupt stack must hold used_bytes. Left out: no proof noted.
    memory.application.isr_stack_guard_evidence object no null Proof note of the guard: used_bytes is the guard tools/stackuse --strict requires for this image (largest frame on the interrupt stack plus the larger of that frame and an exception frame); only method: stackuse, a measurement cannot show it. Required for isr_stack_guard_size below the default in an ASIL project, otherwise a warning. The guard must hold used_bytes. Left out: no proof noted.

    memory.application.isr_stack_evidence¶

    Proof note of a BSW task stack: what the task uses of its stack and where that is shown.

    Field Type Unit Required Default Allowed values Description
    memory.application.isr_stack_evidence.method string yes stackuse, high_water_mark stackuse: worst case of the static analysis tools/stackuse for the image of this project. high_water_mark: high-water mark measured at the board (console stats) after the deepest paths of the task have run (covers only what ran).
    memory.application.isr_stack_evidence.used_bytes integer byte yes > 0 Stack the task uses according to the proof (worst case of tools/stackuse, or the measured high-water mark); the stack of the task must hold it.
    memory.application.isr_stack_evidence.reference string yes at least 1 character Where the proof is: report file and image (version, commit), or measurement record (date, build, test steps).

    memory.calibration¶

    Calibration segment: the values of all calibration parameters (rte::PARAMETERS) in a flash area of their own, behind a CALV header (magic, format, layout identifier, length, CRC-32). The application checks the header at start-up and reacts as on_invalid says. tools/nxconfig/memory.py places it: in the code flash of memory.flash directly behind the first sector of the application (the vector table stays where the bootloader jumps to), so the download of the application does not grow over the whole flash.

    Field Type Unit Required Default Allowed values Description
    memory.calibration.region string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ Flash region of the derivative the segment lies in: the code flash of memory.flash, or a data flash region (kind data_flash). A data flash can only be written separately, which the bootloader learns with BL-31 (NVM-12); until then it is refused with that reason.
    memory.calibration.size integer byte yes > 0 Size of the segment, whole sectors of the region: 32 bytes of header plus the values of all calibration parameters (the linker checks that they fit).
    memory.calibration.on_invalid string no "refuse" refuse, defaults, warn Reaction at start-up when the header, the layout identifier or the CRC of the segment does not fit the application. refuse: the application functions (RTE runnables) do not start, the ECU stays reachable over UDS for a new download; required as soon as one parameter is safety relevant (safety of swc.yaml other than qm). defaults: the values built into the application image, development profile only. warn: the values of the segment as they are. Each reaction other than a valid segment is logged and reported to the fault memory (BSW event calibration.segment).
    memory.calibration.profile string no "development" development, production development: the values are copied into a RAM working page at start-up, XCP calibrates there, the flash segment is the reference page. production: the values are read directly from the flash segment, there is no RAM copy and no write path; the project must not have an xcp section.

    nvm¶

    Non-volatile memory of the project: partition of the emulated EEPROM, block definitions and places.

    Field Type Unit Required Default Allowed values Description
    nvm.partition object no null Partition of the emulated EEPROM. Left out: the chip is used as it is, no partition command is built.
    nvm.blocks map of string to object no {} key: at least 1 character, pattern ^[A-Za-z0-9_]+$ Definition (NVM-18: type, length, integrity), place and write policy per NvM block; key: block name (nvm.<Block> of rte.yaml, or DemEvents/DemEntries of the fault memory).
    nvm.data_flash object no null NVM-12: areas of the data flash (name, size, purpose). Left out: the application does not use the data flash.

    nvm.partition¶

    Split of the emulated EEPROM, in bytes; the generator derives the codes of the partition command from the derivative (eeprom_emulation).

    Field Type Unit Required Default Allowed values Description
    nvm.partition.eeprom_bytes integer byte yes ≥ 0 Bytes of emulated EEPROM (s32k1xx: FlexRAM used as EEPROM). One of the sizes of the derivative.
    nvm.partition.data_flash_bytes integer byte yes ≥ 0 Bytes of the partitionable flash that stay data flash; the rest backs up the emulated EEPROM.
    nvm.partition.partition_code integer none no null 0 to 15 Code of the split in the partition command (s32k1xx: DEPART). Only needed where the derivative has several codes for the same split; it must be one of them.
    nvm.partition.load_on_reset boolean no true true: the chip loads the emulated EEPROM during every reset (s32k1xx: PGMPART FCCOB3 = 0, IFR EEERST = 1 - opposite encodings). false: every start would need a flash command (SETRAM), which the start-up never launches; the NvM would run on its defaults.
    nvm.partition.key_slots integer none no null ≥ 0 NVM-11: key slots of the security module to reserve in the emulated EEPROM (s32k1xx CSEc: 0, 5, 10 or 20; FCCOB1). One of the key space sizes of the derivative; the bytes come off the usable EEPROM. Left out on a derivative with a key space: the partition command refuses to write - the space is fixed with the partition and cannot be added later.
    nvm.partition.key_verify_only boolean no false NVM-11: security flag extension (s32k1xx: SFE, FCCOB2): lets a key be marked verify-only. Not offered yet: the partition command writes it off.

    nvm.blocks.<key>¶

    Definition of one NvM block (NVM-18: data type, scalar or vector, integrity), its place and write policy.

    Field Type Unit Required Default Allowed values Description
    nvm.blocks.<key>.type string no null boolean, uint8, sint8, uint16, sint16, uint32, sint32, float32, float64 NVM-18: platform type of the block's value (of one element of a vector). The ports connected to nvm.<Block> must have this type. Left out: the type comes from the writing port (before NVM-18; the generator warns and proposes the definition). Not for the blocks of the fault memory (DemEvents, DemEntries), whose layout comes from diag.yaml.

    sample_groups.<key>¶

    Board ADC channels converted after every hardware trigger of a PWM group (fast control loop, IO-62).

    Field Type Unit Required Default Allowed values Description
    sample_groups.<key>.pwm string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ PWM group of the project (pwm.<group>) whose trigger output starts the group; the group needs pwm.<group>.trigger.
    sample_groups.<key>.channels list of string none yes 1 to 32 items; item: at least 1 character, pattern ^[A-Za-z0-9_]+$ Board ADC entries (adc[].name) of the group, in the order of the results. Entries on different ADCs are sampled at the same instant, entries on one ADC one after another in this order (nxconfig warns and names the time offset).
    sample_groups.<key>.delay_ns integer ns no 0 0 to 1000000 Time from the trigger point of the PWM group to the start of the first sample. The realised value is a whole number of sequencer clocks (nxconfig shows it).
    sample_groups.<key>.verify boolean no false true: the sampling instant is not confirmed (e.g. not measured on a board).
    sample_groups.<key>.note string no null Free text for the reader; no tool evaluates it.

    bsw_tasks.<key>¶

    Stack of one BSW task, or the task it runs in instead of a task of its own.

    Field Type Unit Required Default Allowed values Description
    bsw_tasks.<key>.stack_bytes integer byte no null > 0 Stack of the task. At least min_stack_bytes of ecu/configuration/taskStacks.yaml and a multiple of its multiple_of (8, the safety task 32: MPU region). Below the default nxconfig warns: confirm the value with the high-water mark (console stats) or tools/stackuse. Left out: the default of taskStacks.yaml.
    bsw_tasks.<key>.run_in string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Merge the task into another BSW task: no FreeRTOS task and no stack of its own, its work runs in the named task at that task's priority (its stack has to hold both). Only the merges taskStacks.yaml lists for the task (run_in); never for or into the safety task. Left out: the task runs on its own.
    bsw_tasks.<key>.evidence object no null Proof note of the stack (tools/stackuse or high-water mark at the board). Required for a stack below the default in an ASIL project (project.integrity not qm), otherwise a warning. Left out: no proof noted.
    bsw_tasks.<key>.note string no null Free text for the reader; no tool evaluates it.

    bsw_tasks.<key>.evidence¶

    Proof note of a BSW task stack: what the task uses of its stack and where that is shown.

    Field Type Unit Required Default Allowed values Description
    bsw_tasks.<key>.evidence.method string yes stackuse, high_water_mark Same as memory.application.isr_stack_evidence.method.
    bsw_tasks.<key>.evidence.used_bytes integer byte yes > 0 Same as memory.application.isr_stack_evidence.used_bytes.
    bsw_tasks.<key>.evidence.reference string yes at least 1 character Same as memory.application.isr_stack_evidence.reference.

    console¶

    Console and logger of the application on the terminal UART.

    Field Type Unit Required Default Allowed values Description
    console.enabled boolean no true false: no console (no command input, no console commands of the application) and no logger (log calls do nothing, no ring buffer). The UART stays initialised: the safety lines of the safe supervisor (SAFETY RESET, safety::safeConsoleWrite) and the start-up lines are written to it synchronously in every image. Left out: true.
    console.logger_buffer_bytes integer byte no null 512 to 65536 Size of the logger ring buffer. A full buffer drops the oldest entries (console logger lost counts them); below 8192 bytes the start-up of the eval board lost lines (board 2026-09-18). Left out: 8192.
    console.note string no null Free text for the reader; no tool evaluates it.
