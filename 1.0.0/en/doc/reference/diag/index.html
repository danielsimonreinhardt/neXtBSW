    Diagnostic description (diag.yaml)¶

    Data identifiers, routines, sessions, security levels and the diagnostic trouble codes of one ECU software. The file is named by project.diag in project.yaml, checked against its schema and against itself by tools/nxconfig (with file, line and YAML path, before the build) and read by the UDS job generator, the fault memory generator and the ODX/PDX export. The addresses of the diagnostic connection - CAN identifiers, ISO-TP parameters and the security access of the bootloader - are project values and stand in project.yaml.

    Configuration level: Project. File: projects/<project>/diag.yaml. Schema: DiagDescription in tools/nxconfig/model.py.

    241 fields in 40 objects. 0 fields have no description in the schema and 0 numeric fields have no unit; they are marked missing in schema and missing. How to read the tables: reference overview.

    Diagnostic description file projects/<project>/diag.yaml¶

    (top level)¶

    Diagnostic description of a project (projects/<project>/diag.yaml, named by project.diag).

    What one ECU software answers on the diagnostic connection and what its fault memory stores: sessions, security levels, data identifiers, routines, and the DTCs with their events, debouncing, enable conditions, operation cycle, aging, snapshots and extended data. The addresses of the connection (CAN ids, ISO-TP, bootloader security access) are project values and stand in project.yaml diagnostics.

    The file is a description only. The UDS jobs and the fault memory are generated from it exports it as ODX/PDX.

    Field Type Unit Required Default Allowed values Description
    schema_version integer yes 1 Version of the file format; currently 1.
    sessions list of object no [] Diagnostic sessions of the ECU. Left out: the identifiers and routines name no session and everything is served in every session the UDS stack knows.
    security list of object no [] Security levels of the application. Left out: none (the security access of the bootloader stands in project.yaml).
    operation_cycles list of object no [] Operation cycles of the fault memory; required as soon as a DTC is described.
    enable_conditions list of object no [] Conditions a DTC can wait on before it updates its status. Left out: none.
    data_identifiers list of object no [] Data identifiers the ECU serves.
    routines list of object no [] Routines the ECU serves.
    fault_memory object no null Size and behaviour of the fault memory; required as soon as a DTC is described.
    bsw_dtc_range object no {} Block of DTC numbers of the basic software (neXtBSW range). Left out: 0x160000..0x16FFFF.
    dtcs list of object no [] Diagnostic trouble codes of the fault memory.
    dtc_groups list of object no [] Groups of DTCs the tester can clear with 14 besides all DTCs (0xFFFFFF) and a single DTC (ISO 14229-1, Annex D.1). Left out: none.

    sessions[]¶

    One diagnostic session of the ECU (DiagnosticSessionControl, 10; ISO 14229-1, clause 9.2).

    Field Type Unit Required Default Allowed values Description
    sessions[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the session, unique in the file; identifiers and routines refer to it by this name.
    sessions[].id integer none yes 1 to 126 Session type of the sub-function. 0x01 default, 0x02 programming, 0x03 extended, 0x04 safety system; 0x40..0x5F are left to the manufacturer and 0x60..0x7E to the system supplier. The ranges ISO 14229-1 reserves are an error.
    sessions[].label string no null Readable name for the tester and for the ODX export (LONG-NAME). Left out: the export uses name.
    sessions[].description string no null Sentence for the reader and for the ODX export (DESC).
    sessions[].p2_ms integer ms no 50 > 0 P2 of this session: how long the ECU may take to answer before it has to ask the tester to wait.
    sessions[].p2_star_ms integer ms no 5000 > 0 P2* of this session: how long the tester waits after the ECU asked it to wait.

    security[]¶

    One security level of the application (SecurityAccess, 27; ISO 14229-1, clause 9.4).

    The security access of the bootloader is not described here: it is a project value (project.yaml diagnostics.bootloader.security), because the tester and the provisioning tool have to agree on it before any application exists.

    Field Type Unit Required Default Allowed values Description
    security[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the level, unique in the file.
    security[].level integer none yes 1 to 125 requestSeed sub-function of the level; it has to be odd, the matching sendKey is one higher (ISO 14229-1, clause 9.4).
    security[].label string no null Same as sessions[].label.
    security[].description string no null Sentence for the reader and for the ODX export (DESC).
    security[].method string no "hmac-sha256" hmac-sha256 Method of the key calculation. hmac-sha256: the device key of the bootloader's security access (HMAC-SHA256 of the project master key and the chip UID, provisioned into the key sector) answers the seed; key = the first key_bytes of HMAC-SHA256(device key, "NXAK" + level + seed). The key is bound to the level, so the key of one level unlocks no other level and not the bootloader. seed_bytes and key_bytes at most 32.
    security[].seed_bytes integer byte no 4 1 to 255 Length of the seed the ECU sends.
    security[].key_bytes integer byte no 4 1 to 255 Length of the key the tester answers with.
    security[].attempts integer none no 3 1 to 255 Wrong keys in a row before the ECU refuses further attempts for delay_ms.
    security[].delay_ms integer ms no 10000 > 0 How long the ECU refuses further attempts after attempts wrong keys.
    security[].sessions list of string no null item: at least 1 character, pattern ^[A-Za-z0-9_]+$ Sessions the level can be unlocked in. Left out: every session of the file except the default session.

    operation_cycles[]¶

    One operation cycle of the fault memory (ISO 14229-1, D.2.1): what starts and ends a round of testing.

    The status bits of a DTC that speak about "this operation cycle", the confirmation threshold and the aging counter all count in the cycle named here.

    Field Type Unit Required Default Allowed values Description
    operation_cycles[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the cycle, unique in the file; a DTC refers to it by this name.
    operation_cycles[].label string no null Same as sessions[].label.
    operation_cycles[].description string no null Sentence for the reader and for the ODX export (DESC).
    operation_cycles[].kind string no "power" power, ignition, operation, other What the cycle follows: power (the ECU is supplied), ignition (terminal 15), operation (a manufacturer defined round of operation) or other. The fault memory treats all of them alike; the name is for the reader and the export.
    operation_cycles[].autostart boolean no true true: the cycle starts when the ECU starts and ends when it shuts down. false: the application starts and ends it.

    enable_conditions[]¶

    One condition that has to hold before a DTC may update its status (ISO 14229-1, D.2.1).

    While a condition of a DTC is not fulfilled its monitor result is discarded: the debounce counter keeps its value and no status bit changes.

    Field Type Unit Required Default Allowed values Description
    enable_conditions[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the condition, unique in the file; a DTC refers to it by this name.
    enable_conditions[].label string no null Same as sessions[].label.
    enable_conditions[].description string no null Sentence for the reader and for the ODX export (DESC).
    enable_conditions[].port string no null at least 1 character, pattern ^[A-Za-z][A-Za-z0-9_]*(\.[A-Za-z][A-Za-z0-9_]*){2}$ Provided port element of the ECU description that reports the condition as a boolean, Component.Port.Element. Exactly one of port and bsw.
    enable_conditions[].bsw string no null at least 1 character, pattern ^[a-z][a-z0-9_]*(\.[A-Za-z0-9_]+)+$ Value of the basic software that reports the condition, e.g. ecu.state. Exactly one of port and bsw.
    enable_conditions[].initial boolean no false State of the condition before the source has reported for the first time. false: no DTC waiting on it updates until then.

    data_identifiers[]¶

    One data identifier (DID) the ECU serves with 22 (read) and 2E (write).

    The identifier is checked against the ranges of ISO 14229-1 Annex C.1 and against the identifiers the bootloader already answers (diagdesc.py). The length of the response follows from data.

    Field Type Unit Required Default Allowed values Description
    data_identifiers[].identifier integer none yes 0 to 65535 16-bit data identifier. Must lie in a range Annex C.1 leaves to the manufacturer or the system supplier, must not be one of the identifiers the bootloader answers, and must not appear twice in this file.
    data_identifiers[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the identifier, unique in the file; snapshots refer to it by this name and the export uses it as the short name.
    data_identifiers[].label string no null Same as sessions[].label.
    data_identifiers[].description string no null Sentence for the reader and for the ODX export (DESC).
    data_identifiers[].group string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Free group name the tester can sort jobs by (FUNCT-CLASS), e.g. identification or actuator_test. Left out: no group.
    data_identifiers[].data list of object yes at least 1 item The values of the identifier in the order they stand on the wire; the length of the identifier is their total width.
    data_identifiers[].read boolean no true true: the identifier answers ReadDataByIdentifier (22).
    data_identifiers[].write boolean no false true: the identifier accepts WriteDataByIdentifier (2E). A constant source cannot be written.
    data_identifiers[].read_sessions list of string no null item: at least 1 character, pattern ^[A-Za-z0-9_]+$ Sessions (sessions[].name) the identifier may be read in. Left out: every session of the file.
    data_identifiers[].write_sessions list of string no null item: at least 1 character, pattern ^[A-Za-z0-9_]+$ Sessions the identifier may be written in; see read_sessions. Only with write.
    data_identifiers[].read_security string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Security level (security[].name) that has to be unlocked for reading. Left out: no security access needed.
    data_identifiers[].write_security string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Security level that has to be unlocked for writing; see read_security. Only with write.

    data_identifiers[].data[]¶

    One value inside the data of a data identifier: a parameter plus where its value comes from.

    Field Type Unit Required Default Allowed values Description
    data_identifiers[].data[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the element, unique within its list; the export uses it as the short name of the parameter.
    data_identifiers[].data[].label string no null Same as sessions[].label.
    data_identifiers[].data[].description string no null Sentence for the reader and for the ODX export (DESC).
    data_identifiers[].data[].type string yes uint8, uint16, uint32, int8, int16, int32, float32, ascii, bytes Type on the wire: an integer (uint8, uint16, uint32, int8, int16, int32), float32, a text (ascii) or raw bytes (bytes). ascii and bytes need length_bytes, the others take their width from the type.
    data_identifiers[].data[].length_bytes integer byte no null > 0 Only for ascii and bytes: width of the element on the wire - always exactly this many bytes: a shorter text is filled up with NUL (0x00), a longer one is cut, so that a tester can split a response by the description alone (e.g. several identifiers in one 22 response). For every other type the width follows from type and stating it is an error.
    data_identifiers[].data[].byte_order string no "big" big, little Byte order of an element wider than one byte. big is the order UDS uses for its own parameters and the default here; little only where the value is passed on unchanged from a little endian source.
    data_identifiers[].data[].unit string unit of the described value no null Physical unit of the value as it is shown (e.g. mV, degC, 1/min); the export uses it as the display name of the unit. Left out: the value has no unit (a count, an index, a text, raw bytes).
    data_identifiers[].data[].factor number none no 1.0 finite Physical value = factor * coded value + offset (the linear conversion of the export). Only for numeric types.
    data_identifiers[].data[].offset number none no 0.0 finite Added after factor; see there. Only for numeric types.
    data_identifiers[].data[].min number unit of the described value no null finite Smallest physical value the element takes; the export writes it as the lower limit. Left out: the range of the type.
    data_identifiers[].data[].max number unit of the described value no null finite Largest physical value the element takes; see min.
    data_identifiers[].data[].values list of object no null at least 1 item Text table of an integer element: one entry per coded value (the export writes it as a text table conversion). Only for integer types, and not together with factor, offset, min or max; each coded value only once.
    data_identifiers[].data[].source object yes Where this value comes from: an RTE port, a value of the basic software, or a constant. Every value of an identifier has its own source, so an identifier can mix a fixed byte with a live value (e.g. the number of modules of 0xF180 with the version text).

    data_identifiers[].data[].values[]¶

    One line of a text table: a coded value and what the tester shows for it.

    A list instead of a mapping, because the export writes one entry per line (COMPU-SCALE with its own text) and because the YAML loader of tools/nxconfig reads every mapping key as a string.

    Field Type Unit Required Default Allowed values Description
    data_identifiers[].data[].values[].value integer none yes Coded value as it stands on the wire.
    data_identifiers[].data[].values[].text string yes 1 to 64 characters What the tester shows for this value.

    data_identifiers[].data[].source¶

    Where the data of an identifier comes from: exactly one of the three.

    Field Type Unit Required Default Allowed values Description
    data_identifiers[].data[].source.port string no null at least 1 character, pattern ^[A-Za-z][A-Za-z0-9_]*(\.[A-Za-z][A-Za-z0-9_]*){2}$ Provided port element of the ECU description, Component.Port.Element (rte.yaml components). The value is read through the RTE.
    data_identifiers[].data[].source.bsw string no null at least 1 character, pattern ^[a-z][a-z0-9_]*(\.[A-Za-z0-9_]+)+$ Value of the basic software in the notation of the rte.yaml connections, e.g. ecu.state or adc.mv.<CHANNEL>. Which names exist is resolved by the RTE generator, not here.
    data_identifiers[].data[].source.constant integer or string unit of the element it fills no null Fixed value that does not change at runtime (e.g. a hardware number or the number of modules of 0xF180). A text for ascii, a number for a numeric element; it has to fit the element (checked in diagdesc.py).

    routines[]¶

    One routine the ECU serves with RoutineControl (31).

    The identifier is checked against the ranges of ISO 14229-1 Annex F.1 and against the routines of the bootloader (diagdesc.py).

    Field Type Unit Required Default Allowed values Description
    routines[].identifier integer none yes 0 to 65535 16-bit routine identifier. Must lie in a range Annex F.1 leaves to the manufacturer or the system supplier and must not appear twice in this file.
    routines[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the routine, unique in the file.
    routines[].label string no null Same as sessions[].label.
    routines[].description string no null Sentence for the reader and for the ODX export (DESC).
    routines[].group string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Same as data_identifiers[].group.
    routines[].start object yes startRoutine (sub-function 01); every routine has one.
    routines[].stop object no null stopRoutine (sub-function 02). Left out: the routine cannot be stopped.
    routines[].results object no null requestRoutineResults (sub-function 03). Left out: the routine reports no result of its own.
    routines[].sessions list of string no null item: at least 1 character, pattern ^[A-Za-z0-9_]+$ Sessions (sessions[].name) the routine may run in. Left out: every session of the file.
    routines[].security string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Security level (security[].name) that has to be unlocked. Left out: none.

    Field Type Unit Required Default Allowed values Description
    routines[].start.call object yes What the step runs: a runnable of a component or a service of the basic software.
    routines[].start.request list of object no [] Parameters the tester sends with this step, in wire order. Left out: none.

    What one step of a routine runs: exactly one of the two.

    Field Type Unit Required Default Allowed values Description
    routines[].start.call.runnable string no null at least 1 character, pattern ^[A-Za-z][A-Za-z0-9_]*\.[A-Za-z][A-Za-z0-9_]*$ Runnable of a component of the ECU description, Component.Runnable.
    routines[].start.call.bsw string no null at least 1 character, pattern ^[a-z][a-z0-9_]*(\.[A-Za-z0-9_]+)+$ Service of the basic software in the notation of the rte.yaml connections, e.g. bsw.reset.request. Which names exist is resolved by the RTE generator, not here.

    routines[].start.request[]¶

    One value on the wire: a parameter of a routine request or response.

    Everything an ODX export needs to describe the value on the wire and in physical units is here: the coded type (type, length_bytes, byte_order), the conversion to the physical value (factor, offset, unit, or values for a text table) and its range (min, max). The byte position follows from the order of the list, the total length from the parameters - neither is configured.

    The data of an identifier uses DiagDataElement, which adds where the value comes from.

    Field Type Unit Required Default Allowed values Description
    routines[].start.request[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Same as data_identifiers[].data[].name.
    routines[].start.request[].label string no null Same as sessions[].label.
    routines[].start.request[].description string no null Sentence for the reader and for the ODX export (DESC).
    routines[].start.request[].type string yes uint8, uint16, uint32, int8, int16, int32, float32, ascii, bytes Same as data_identifiers[].data[].type.
    routines[].start.request[].length_bytes integer byte no null > 0 Same as data_identifiers[].data[].length_bytes.
    routines[].start.request[].byte_order string no "big" big, little Same as data_identifiers[].data[].byte_order.
    routines[].start.request[].unit string unit of the described value no null Same as data_identifiers[].data[].unit.

    fault_memory¶

    Size and behaviour of the fault memory as a whole (simplified AUTOSAR DEM).

    Field Type Unit Required Default Allowed values Description
    fault_memory.max_entries integer none yes 1 to 255 DTCs the memory holds at the same time. Fewer than the described DTCs is allowed (not all of them are stored at once) and is reported as a warning.
    fault_memory.overflow string no "replace_oldest" replace_oldest, keep_oldest What happens when the memory is full and a further DTC matures: replace_oldest displaces the least important, oldest entry (see priority), keep_oldest discards the new one.
    fault_memory.snapshot_records_max integer none no 1 0 to 254 Snapshot records stored per DTC. 0: no snapshots are stored.
    fault_memory.extended_records_max integer none no 1 0 to 143 Extended data records stored per DTC. 0: none.
    fault_memory.aging_cycle string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Operation cycle the aging of a DTC counts in when the DTC names none. Left out: the cycle of the DTC.
    fault_memory.cycle_ms integer ms no 10 1 to 1000 Cycle of the fault memory: every event is sampled once per cycle, so a counter debouncing of n samples takes n cycles, and time debouncing counts in steps of this. Reported BSW events are taken over once per cycle as well.
    fault_memory.write_interval_ms integer ms no 1000 0 to 3600000 Shortest distance between two writes of a changed fault memory block to the persistent memory (NvM write policy CHANGE, wear of an EEPROM emulation); the run-down writes what is left. 0: only at the run-down.

    bsw_dtc_range¶

    The block of DTC numbers the basic software raises its own DTCs in (configurable since an earlier change).

    Numbering plan and default: tools/nxconfig/bswdtc.py. A DTC of a BSW event the plan knows leaves number out and gets base + the offset of its source, so moving the base moves every BSW DTC. Project DTCs are numbered outside the range (a project DTC inside it is reported as a warning).

    Field Type Unit Required Default Allowed values Description
    bsw_dtc_range.base integer none no 1441792 256 to 16776704 First number of the range; it is also the group identifier of the whole range and never a DTC. A multiple of 0x100. Left out: 0x160000 (P16xx-yy, the default of neXtBSW).
    bsw_dtc_range.size integer none no 65536 256 to 16776704 Numbers in the range, a multiple of 0x100 (one block per source of the plan). Below 0x900 the later sources of the plan have no number. Left out: 0x10000.

    dtcs[]¶

    One diagnostic trouble code of the fault memory.

    The number is a 3-byte DTC in the ISO 14229-1 format (Annex D.4, format identifier 0x01); the ranges Annex D.1 reserves for legislation and for the group identifiers are checked in diagdesc.py. Warning lamp and OBD are deliberately not described (a project decision, 2026-09-21): the status byte has no warningIndicatorRequested source here and the OBD class bits of Annex D.3.3 stay at the unclassified value.

    Field Type Unit Required Default Allowed values Description
    dtcs[].number integer none no null 0 to 16777215 3-byte DTC number. 0x000000..0x0000FF is reserved for legislation and 0xFFFF00..0xFFFFFF are the group identifiers (Annex D.1); the number must not appear twice in this file. Left out: only for an event of the basic software that the neXtBSW numbering plan knows (tools/nxconfig/bswdtc.py) - the number is bsw_dtc_range.base plus the offset of the plan, so it follows the range of the project.
    dtcs[].bsw_instance integer none no null 0 to 255 Low byte of a derived number for a BSW source with instances: index of the used CAN bus for can.busoff.<BUS>, cause for safety.<cause>, NvM block index for nvm.*.<BLOCK>. Only with number left out and only for such a source.
    dtcs[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the DTC, unique in the file.
    dtcs[].label string no null Same as sessions[].label.
    dtcs[].description string no null Sentence for the reader and for the ODX export (DESC).
    dtcs[].group string no null at least 1 character, pattern ^[A-Za-z0-9_]+$ Same as data_identifiers[].group.
    dtcs[].display_code string no null 1 to 16 characters, pattern ^[A-Za-z0-9_-]+$ Code the tester shows instead of the number (e.g. P061600), for the ODX export (DISPLAY-TROUBLE-CODE). It is not derived: this description uses the ISO 14229-1 DTC format (Annex D.4, 0x01), which fixes no display text. Left out: the export has none and the tester shows the number - except for a derived BSW number (number left out), which gets its SAE J2012 display (0x160100: P160100).
    dtcs[].severity string no "none" none, maintenance_only, check_at_next_halt, check_immediately Severity of the DTC (Annex D.3.2, bits 7..5 of the severity byte): none, maintenance_only, check_at_next_halt or check_immediately.
    dtcs[].event object yes The monitor whose result sets and clears the DTC.
    dtcs[].debounce object yes How the raw monitor result becomes a matured test result.
    dtcs[].operation_cycle string yes at least 1 character, pattern ^[A-Za-z0-9_]+$ Operation cycle (operation_cycles[].name) the status bits, the confirmation and the aging of this DTC count in.
    dtcs[].enable_conditions list of string no [] item: at least 1 character, pattern ^[A-Za-z0-9_]+$ Conditions (enable_conditions[].name) that all have to hold before the status of this DTC is updated. Left out: none.
    dtcs[].confirmation_threshold integer none no 1 1 to 255 Operation cycles with a failed test before the confirmed bit is set and the entry is stored (Annex D.2.1). 1: the first failed test confirms.
    dtcs[].aging object no null When a confirmed DTC is forgotten again. Left out: it is kept until the tester clears it.
    dtcs[].priority integer none no 1 1 to 255 Which DTC wins when the fault memory is full: 1 is the most important entry, a larger number is displaced first.
    dtcs[].snapshots list of object no [] Snapshot records of this DTC. Left out: none.
    dtcs[].extended_data list of object no [] Extended data records of this DTC. Left out: none.

    dtcs[].event¶

    The monitor whose result sets and clears one DTC: exactly one source.

    Every DTC has an event; a DTC nothing can set is a description of nothing and is reported as an error.

    Field Type Unit Required Default Allowed values Description
    dtcs[].event.port string no null at least 1 character, pattern ^[A-Za-z][A-Za-z0-9_]*(\.[A-Za-z][A-Za-z0-9_]*){2}$ Provided port element of the ECU description that reports the test result, Component.Port.Element.
    dtcs[].event.bsw string no null at least 1 character, pattern ^[a-z][a-z0-9_]*(\.[A-Za-z0-9_]+)+$ Monitor of the basic software that reports the test result, e.g. can.busoff.<BUS>. Which names exist is resolved by the RTE generator, not here.
    dtcs[].event.description string no null What the monitor tests, for the reader and the export.
    dtcs[].event.result string no null boolean, qualifier, status, limit How the value of the source becomes a test result, sampled once per fault memory cycle (fault_memory.cycle_ms): boolean (true: failed), qualifier (a signal qualifier of Rte_Qlf.h: QLF_OK passed, QLF_DEBOUNCE no result, every error failed), status (the AUTOSAR event status: 0 passed, 1 failed, 2 prepassed, 3 prefailed, other values no result) or limit (failed_above/failed_below). Left out: derived by the RTE generator - limit if a limit is given, qualifier for a qualifier source, boolean for a boolean port. A source the BSW reports itself (a bsw name the RTE does not know) reports AUTOSAR event states through dem::IFaultMemory::report().
    dtcs[].event.failed_above integer none no null limit: the sample is failed while the value is above this (in the unit of the source), passed otherwise.
    dtcs[].event.failed_below integer none no null limit: the sample is failed while the value is below this.

    dtcs[].debounce¶

    How the raw result of a monitor becomes a matured test result: exactly one of the two ways.

    Field Type Unit Required Default Allowed values Description
    dtcs[].debounce.counter object no null Debouncing by counting test samples.
    dtcs[].debounce.time object no null Debouncing by time.

    dtcs[].debounce.counter¶

    Debouncing by counting test samples (AUTOSAR DEM counter debouncing).

    Every failed sample moves the counter up by increment, every passed sample down by decrement. At failed_threshold the DTC is failed, at passed_threshold it is passed. The counter is the fault detection counter ISO 14229-1 D.6 describes.

    Field Type Unit Required Default Allowed values Description
    dtcs[].debounce.counter.failed_threshold integer none no 127 1 to 127 Counter value at which the test counts as failed.
    dtcs[].debounce.counter.passed_threshold integer none no -128 -128 to -1 Counter value at which the test counts as passed.
    dtcs[].debounce.counter.increment integer none no 1 1 to 255 Step of one failed sample.
    dtcs[].debounce.counter.decrement integer none no 1 1 to 255 Step of one passed sample.
    dtcs[].debounce.counter.jump_up integer none no null -128 to 127 Value a counter below it jumps to on a failed sample, before the sample adds increment. Left out: 0 - the first failed sample after passed ones moves the counter over zero, so the DTC is prefailed at once (ISO 14229-1, D.6).
    dtcs[].debounce.counter.jump_down integer none no null -128 to 127 Value a counter above it jumps to on a passed sample, before the sample subtracts decrement. Left out: 0 (the first passed sample after failed ones moves it below zero).

    dtcs[].debounce.time¶

    Debouncing by time: the monitor has to report the same result for this long before it counts.

    Field Type Unit Required Default Allowed values Description
    dtcs[].debounce.time.failed_ms integer ms yes > 0 How long the monitor has to report failed without interruption before the test counts as failed.
    dtcs[].debounce.time.passed_ms integer ms yes > 0 How long the monitor has to report passed without interruption before the test counts as passed.

    dtc_groups[]¶

    A group of DTCs a tester clears with ClearDiagnosticInformation (14).

    group is the 3-byte groupOfDTC value the tester sends, first..last the DTC numbers it stands for. ISO 14229-1, Annex D.1 leaves the groups to the vehicle manufacturer and reserves 0xFFFF00..0xFFFFFE for the functional groups (e.g. 0xFFFF33 emissions, 0xFFFFD0 safety); 0xFFFFFF (all DTCs) and a single DTC number need no entry. Checked in diagdesc.py, generated by tools/diaggen as the table diagDtcGroups() of ecu/uds.

    Field Type Unit Required Default Allowed values Description
    dtc_groups[].name string yes 1 to 64 characters, pattern ^[A-Za-z][A-Za-z0-9_]*$ Name of the group, unique in the file.
    dtc_groups[].bsw boolean no false true: the group of the whole neXtBSW range - group, first and last are derived from bsw_dtc_range (base, base, base + size - 1) and are left out.
    dtc_groups[].group integer none no null 0 to 16777215 groupOfDTC value of the group (Annex D.1): a group of the vehicle manufacturer or a functional group 0xFFFF00..0xFFFFFE. Not 0xFFFFFF (all DTCs) and not the number of a described DTC; unique in the file. Required unless bsw is true.
    dtc_groups[].first integer none no null 0 to 16777215 Lowest DTC number of the group. Required unless bsw is true.
    dtc_groups[].last integer none no null 0 to 16777215 Highest DTC number of the group (at least first, below the group identifiers 0xFFFF00). Required unless bsw is true.
    dtc_groups[].label string no null Same as sessions[].label.
    dtc_groups[].description string no null Sentence for the reader and for the ODX export (DESC).
