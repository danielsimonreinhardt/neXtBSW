    K2: Reaktionen und sichere Zustände¶

    %%{init: {'theme':'base','flowchart':{'curve':'basis'},'themeVariables':{'fontFamily':'Segoe UI, Helvetica, Arial, sans-serif','fontSize':'14px','background':'#ffffff','primaryColor':'#ffffff','primaryBorderColor':'#64748b','primaryTextColor':'#0f172a','lineColor':'#475569','edgeLabelBackground':'#ffffff','tertiaryColor':'#f8fafc','clusterBkg':'#f8fafc','clusterBorder':'#cbd5e1'}}}%%
stateDiagram-v2
    state "normal operation" as RUN
    S3: S3 log and continue
    SD: SD mapped groups degraded
    S1: S1 outputs off
    HELD: S1 held
    S1S2: S1 + S2

    [*] --> RUN
    RUN --> S3: SM-05, SM-34 report
    S3 --> RUN
    RUN --> SD: degradable event, mapped
    SD --> SD: more groups
    SD --> S1: last working group
    RUN --> S1: SM-22
    S1 --> RUN: leaveSafeState, indicator only
    RUN --> HELD: SM-07, SM-14, SM-50, SM-34
    RUN --> S1S2: most events
    S1S2 --> RUN: reset, restart
    S1S2 --> HELD: reset-loop limit
    HELD --> [*]: power cycle
    SD --> [*]: power cycle

    Legende

    • Eine Stelle entscheidet: SafeSupervisor::handle(). Ein Mechanismus meldet nur.
    • S1 ist eine Einbahnstraße nach oben: leaveSafeState() gibt nur die Anzeige frei, eine Leistungsstufe kommt nur über ein ausdrückliches enable() ihres Treibers zurück.
    • S1 held: alle Interrupts gesperrt, Tabelle zyklisch neu geschrieben, MCU-Watchdog bedient; Ende nur durch Aus- und Einschalten oder Reset von außen.
    • SD: nur Ereignisse der geschlossenen Liste (DEVICE_FAULT außer IDENTITY, Auslösung eines Hardware-Abschaltpfads HW_SHUTOFF), nur wenn das Projekt sie abbildet; Fehler der MCU selbst nie. Gruppen sammeln sich, nur Aus- und Einschalten beendet SD.
    • S3 ist nur zulässig, wo die Analyse zeigt, dass innerhalb der FTTI kein Sicherheitsziel verletzt wird (SM-05: Reaktion bei der Anwendung, AoU-18).

    Quelle: Konzept Ausgabe 3, Abschnitt 3.

    Legende

    • Balken: garantierte Werte der Tabelle 7.2 bis „Ausgänge stromlos“, jeweils zuzüglich des Tabellendurchlaufs (< 1 µs gerechnet, am Board ≤ 21 µs begrenzt). Nominal sind die Prüfungen im Safety-Task 10 ms, SM-19 100 ms, SM-20 60 ms; SM-01 sind 250 ms bei nominalem LPO, bis etwa 283 ms über den LPO-Bereich.
    • Nicht im Balken: Restrisiko DF-05 (SIRC verloren): kein Tabellendurchlauf vor dem Watchdog-Reset nachgewiesen, höchstens etwa 283 ms. SM-05 schaltet nichts ab (nur Log).
    • Grundwerte (Demo-Projekt): Safety-Task 10 ms, Watchdog-Bedienung alle 70 ms, Watchdog-Zeitablauf 250 ms; geprüft wird 3 × 70 ms = 210 ms ≤ 230,2 ms (Zeitablauf beim schnellsten LPO).
    • Ein Reset ist nicht sofort: der Neustart dauert am Eval Board bis 1 077 ms (Watchdog-Weg) bzw. 858 ms (MPU-Fehler).
    • Das Element legt keine FTTI fest; der Integrator vergleicht je Ziel (AoU-05).
