    neXtBSW documentation¶

    neXtBSW is a hardware-neutral, configurable basic software for 32-bit ARM Cortex-M and Cortex-R automotive MCUs, built on Eclipse OpenBSW. Applications are attached as Simulink models (AUTOSAR Classic SWC) through a generated RTE.

    This page is the map. It tells you where to look; it does not repeat what the linked documents say.

    Reading paths¶

    R1 is a development release; it makes no safety claim. The safety documents describe the target (ASIL B, safety element out of context) and what is still open.

    Language¶

    Published documentation is written in English. The changelog stays German: it is the working log of this project, written and read by its author, and translating it would cost more than it is worth. The full rule, including what it means for code comments and commit messages, is in ../CONTRIBUTING.md.

    All documents under architecture/ are English since an earlier change (2026-09-19); the file names stayed German so that existing references keep working. Some module documents under libs/ are still German and follow as a separate step. Anything new or rewritten is English from the start. Exception until a follow-up task translates them: the short pages under architecture/ for what is planned after R1 (planned.md, non-cortex-m-audit.md, rm4x-quellen.md, stm32-nucleo.md), the short page openbsw-beitraege/README.md and the shortening notes at the head of the shortened pages are German.

    How this folder is organised¶

    doc/
  README.md        this page — the map
  guide/           task-oriented documentation for users: getting started, how-to guides
  reference/       look-up material, generated from the schema, from libs/ and from the console code
  architecture/    how and why the software is built the way it is, plus binding decisions
  safety/          safety concept, safety manual, analyses and work products (target ASIL B)

    guide/, reference/ and architecture/ each have a README.md that says what belongs in it. The split is by what the reader wants (learn, do, look up, understand), not by component, so a page keeps its place as the software grows.

    The same pages are built into a documentation website with MkDocs Material (mkdocs.yml in the repository root): search, German/English switcher, Mermaid, navigation along the reading paths above. It takes this folder plus README.md, the module documents next to the code and the tool READMEs, without moving files: one folder per navigation section, each with a README.md as the section index page, and only relative links between documents. The public site is built from the exported tree, so it holds exactly the published pages; how to build it: tools/docgen/website.md.

    Not covered here, on purpose:

    • Hardware documents — the datasheets and schematics under hardware/ are manufacturer documents. They are kept locally for development; redistribution is not covered by their terms.
    • neXtBSW Studio — the desktop tool under tools/studio is proprietary and is not part of the open source project, so it has no documentation in this tree.
