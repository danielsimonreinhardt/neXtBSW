# Pin edge contract (`bspPinEdge`)

Hardware-neutral interfaces between the pin-interrupt dispatcher of a family and the modules that consume pin
edges (IO-52, concept [`pin-interrupts.md`](../../../../doc/architecture/pin-interrupts.md), section 3.1). The
dispatcher owns the vectors of the pin interrupts; every pin with a consumer is assigned to exactly one consumer and
channel by a static table generated from the project - nothing registers itself at run time.

It is a catalogue entry only (`kind: contract`): `tools/nxconfig` and `tools/bswgen` assign no board device, take no
project values and generate nothing for it.

**State:** verification `mock` - host tests of the s32k1xx dispatcher and of the Hall access through it; no pin
interrupt has been exercised on a board yet (see [Tests](#tests)).

## Interface

Header `pinEdge/IPinEdgeConsumer.h`, CMake target `bspPinEdge` (INTERFACE), namespace `bsp::pinedge`.

| Interface | Method | Behaviour |
|---|---|---|
| `IPinEdgeConsumer` | `void onEdge(uint16_t channel, uint32_t timestampUs)` | pure virtual, implemented by a consumer. Called in interrupt context for every flagged pin of the consumer. `channel` is the consumer's own index (sensor set, event), not a pin number; several pins may share a channel. `timestampUs` is the 32-bit microsecond system time, taken once per interrupt after the flags were cleared |
| `IPinEdgeControl` | `bool setArmed(IPinEdgeConsumer const& consumer, uint16_t channel, bool armed)` | implemented by the dispatcher. `false` switches the edge detection of every pin of (`consumer`, `channel`) off and clears their pending flags; `true` clears them and arms the configured edge again. Returns `false` when the table has no such pin |

Both destructors are protected and non-virtual: the objects are static and never deleted through the interface.

## Configuration

The contract itself has no keys. The table behind it (pin, edge, consumer, channel; vectors with their NVIC level)
comes from the project: the Hall sensor sets (`hall`) and the pin events of `pin_events` (IO-53/IO-54), generated by
tools/bswgen (`bsp/pinIrq/pinIrqConfiguration.h` on s32k1xx, vectors from the derivative fact `pin_interrupts`).

## Behaviour

- `onEdge()` runs inside the ISR frame of the family (safety hooks), may not call the RTOS and has to be short and
  bounded. A consumer that needs the level samples it itself.
- Two flags of one channel in the same interrupt give two calls with the same time.
- `setArmed()` may be called from a task or from `onEdge()` (a rate limit switching its own input off). Calls for one
  channel belong to one context.

> Example (s32k1xx implementation `bios::PinIrqDispatcher`, `platforms/s32k1xx/bsp/bspPinIrq`, not part of the
> contract): one vector per port on the S32K14x, one for all ports on the S32K11x; the edge is `PORT_PCR.IRQC`
> (rising, falling or both - never a level); the interrupt reads `PORT_ISFR`, clears only the flags of pins with a
> consumer and walks only the flags that are set. Start-up in two steps (`init()` arms and clears with the vectors
> off, `enable()` sets the NVIC level and enables them) so consumers can start from the levels in between. The table
> type and its compile-time checks are `pinIrq/PinIrqTable.h`; the port builds the table in
> `bspConfiguration/src/bsp/pinIrq/PinIrqConfig.cpp`.

## Limits and known gaps

- The only implementation is the s32k1xx dispatcher. Other families (S32K3 SIUL2, STM32 EXTI, RM4x GIO) bring their
  own when their port gets pin events; the derivative fact `pin_interrupts` in `mcudb` already describes them.
- An edge chosen at run time (the pin events debounce with both edges, else the configured one) is not part of
  the contract: the s32k1xx adapter uses `PinIrqDispatcher::setEdge()` of the family directly (IO-54). A second
  family with pin events decides whether that becomes a contract function.
